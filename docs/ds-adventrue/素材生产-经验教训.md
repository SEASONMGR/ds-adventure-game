# 素材生产经验教训（ds-adventure）

> 全部来自实测，不是推测。新会话接手前先读这份。

## 零、不要让模型画"反解剖"的状态（缺鳞/半透明/发光缺口）★最严重

**症状**：CG 里角色变成**巨型棱纹发光晶体柱 + 一只悬浮的手**，人物本体消失。连试 6 个画师风格全崩。

**根因**：prompt 里写了
`translucent body, missing scales, glowing gaps in body, reaching hand toward viewer, close-up`
—— "半透明身体 + 九处发光缺口 + 伸手特写"**违反模型的解剖先验**，模型只能把它理解成一根发光的
分节晶体（它认得"发光的鳞/节"这种形状），于是把四肢渲染成晶体柱。

**排查过程**（隔离变量）：
| 变量 | 结果 |
|---|---|
| `absurdres` + 画师前置 | ❌ 崩 |
| 去掉 absurdres，ask 前置 | ⚠️ 脸出来了，但手臂仍是发光晶体柱 |
| 去掉 absurdres，ask 后置 | ⚠️ 同上 |
| 无画师 + absurdres | ❌ 崩 |

→ **`absurdres` 会加剧，但不是根因；根因是那组反解剖描述。**

**正确做法**：
1. prompt 里**只写正常解剖**（"reaching out, outstretched hand, tearful eyes"），
   **绝不写** `translucent / see-through / glowing gaps / missing scales` 这类词
2. **"缺鳞半透明"用后处理做** —— 已有工具 `make_defect_form.py`：
   全局 alpha 0.8 + 九处鳞形缺口（挖洞 + 青色辉光边）+ 轮廓辉光，位置固定、跨图一致
3. 负向加 `glowing arm, crystal arm, oversized arm, translucent skin` 兜底

**通用原则**：**模型画"结构"，脚本画"效果"。** 凡是违背解剖/材质常识的状态（半透明、缺件、
发光孔洞、破碎），都该在生成之后用图像处理叠加，而不是写进 prompt 让模型猜。

## 一、提示词：遮挡区域必须显式描述

**教训**：用官方参考图做 i2i/Edit 时，**参考图里被挡住的部位，提示词里必须写清它应该长什么样**，否则模型会脑补。

**实例**：GLM娘 的参考图里，胸前被黑书挡住。我用 Qwen-Edit 换姿势（把手放下）时没描述"书后面是什么"，模型就自己加了一颗**大蓝宝石胸针** —— 因为遮挡区域在参考图里没有信息，模型只能编。

**规则**：
- 换姿势/换角度前，先列出参考图里**被遮挡或看不到的部位**（胸口、后背、裙内侧、手部、脚部…）
- 在 prompt 里逐一描述这些部位（如"白色立领衬衫，胸前为黑色纽扣排，无胸针"）
- 反向里加 `invented accessory, added jewelry, random ornament` 兜底

## 二、表情差分：面部 inpaint 的两个硬前提

### 2.1 遮罩必须只盖"纯脸皮肤区"
- **不能圈进头发**：刘海/鬓发被重绘会糊成一团（GLM娘 第一版遮罩偏左偏上，圈进刘海 → 脸崩）
- **不能圈进手**：手指被重绘会变成畸形爪子（GLM娘 手指抵唇的姿势 → 手崩）
- **判定方法**：先出遮罩预览图（红区叠底图），确认红区边界在皮肤内、避开手和发

### 2.2 姿势决定可行性
- 手/物件压在脸上（托腮、抵唇、遮嘴）→ **没法做干净的表情差分**：要改嘴就必须盖住手指，要避开手指就改不到嘴
- 正确做法：**先换姿势**（大改动走 Qwen-Edit，把脸空出来）→ 再做表情差分
- 代价：换姿势会让形象漂移（GLM娘 换姿势后帽形/发长/领口都变了），需要接受或多次抽卡

### 2.3 参数经验值
| 项 | 值 | 说明 |
|---|---|---|
| denoise | **0.70** | 常规表情；太小改不动，太大嘴会画变形 |
| denoise | **0.85** | 脸小/刘海厚的角色（Kimi娘）——0.70 推不动，必须提高 |
| denoise | **0.55** | 抑制"嘴画得过大过低"（qiguan panic 就是这个毛病） |
| 遮罩 rx/ry | 按角色实测 | 脸小要放大（Kimi 从 0.040→0.048），否则差分看不出来 |

### 2.3b ★ 面部 inpaint 必须用**极简"表情优先"prompt**（最重要的发现）

**症状**：遮罩位置正确、denoise 提到 0.88，表情还是几乎不变（初音未来 连试三次都失败）。

**根因**：**长 prompt 里的角色描述把表情信号稀释了**。面部 inpaint 的 prompt 里堆满
`hatsune miku, twintails, aqua hair, necktie, pleated skirt, thighhighs, boots…` 时，模型的注意力
被角色身份标签占满，`crying, tears` 这种表情 tag 权重被压到几乎无效。

**解法**：面部 inpaint 的 prompt **只写表情 + 最少的身份锚点**，服装/场景**全部交给回贴**：

```
masterpiece, best quality, score_7, newest, year 2025, highres, safe,
crying, tears, teary eyes, trembling lips,          ← 表情 tag 放最前
1girl, hatsune miku, aqua hair, aqua eyes, face close-up, white background,
tears welling up and rolling down her cheeks        ← 表情句紧随其后
```

**效果对比（同一底图、同一遮罩、同一 denoise）**：
| prompt | cry 的效果 |
|---|---|
| 长 prompt（含全套服装描述） | 几乎没有变化 ❌ |
| 极简表情优先 | **泪流满面 + 脸红 + 悲伤眼** ✅ |

**原理**：遮罩外的像素由 `composite_back` 从底图回贴，**服装/头发/背景本来就不需要模型去画**，
prompt 里描述它们纯属浪费注意力预算，还会跟表情指令竞争。

反向建议同时加 `changed hairstyle, changed outfit` 兜底。

### 2.4 逐像素一致性的保证
- 只用遮罩采样**不够**：VAE 编解码往返会让细线条处偏移最多 107/255
- 必须**出图后用底图回贴遮罩外区域**（`composite_back`），实测才能做到 max diff = 0
- 验证脚本：比对"遮罩外像素"与底图，必须为 0

## 三、抠图

### 3.1 角色立绘必须用 rembg（语义分割），**不能用白底键控** ★

**症状**：交付的立绘"灰灰的、发白、有纹理的灰"。

**根因（实测数据）**：白底键控的 alpha 公式是 `alpha = f(255 - min(r,g,b))` —— **它按"颜色离白多远"判断前景**，于是角色自身的浅色部位（白衬衫、浅肤色、银白发）被判成背景：
- 半透明像素占比 **15~17%**（正常应为 1~2%）→ 角色整体半透明 → 看着发灰
- 透明区 RGB 被去白边公式算成 **[0,0,0] 纯黑** → 引擎缩放时黑边渗入 → "有纹理的灰"

**正确做法**：

| 素材类型 | 工具 |
|---|---|
| **角色立绘**（有白衬衫/浅发/肤色） | **rembg（isnet-anime）** —— 语义分割，认得"这是衣服"，不会吃掉浅色 |
| 扁平贴纸（纯色块、水彩、低饱和） | 白底键控 + 去白边（rembg 对这些反而失效，见 3.2） |

**体检指标**（每次抠完必查）：
- 半透明像素占比 ≤ 2~5%（>10% 说明浅色被吃了）
- 透明区 RGB **不应为纯黑**（应为边缘色；否则有暗边风险）

### 3.2 rembg 失效的场景
- 对**浅色/水彩/低饱和**的扁平素材给出 alpha 1~32 的淡 matte，前景几乎全丢（GLM娘 的水彩小鲸鱼、心形/水泡贴纸都中过招）
- 此时才用白底键控：`alpha = clip((255 - min(r,g,b) - lo) * 255/(hi-lo))`，`lo=8, hi=40`
- 去白边：半透明像素按 `true = (rgb - (1-a)*255)/a` 反解 —— **注意 a=0 的像素会被算成纯黑**，必须只对 `0 < a < 1` 的像素做，或随后用边缘补色修回

### 3.3 边缘补色（防暗边）
透明区保留黑/背景色时，引擎双线性缩放会把它们渗进边缘形成暗边。标准做法是把角色的边缘色"外扩"到透明区（`cutout.py::pad_edges`）。
- 只需外扩几像素（滤波只采样 1~2 像素邻域）
- 当前实现只填了 12 像素环，远处背景仍为黑 —— 实测在 100%/40% 缩放 × 深底/浅底四种组合下**无可见暗边**，够用；要严格干净就把 passes 调大或改全图最近邻填充

## 四、角色一致性（本项目最重要的一条）

| 手段 | 效果 | 用在哪 |
|---|---|---|
| **角色 LoRA** | 最强（精确设计被编码） | ds娘（已有 `ds_chan_lora`） |
| **官方参考图 i2i**（denoise 0.45） | 强（可辨识特征保住） | 有官方图的 6 个 AI 娘 |
| **Qwen-Edit 参考图模式** | 强（特征级），但改动大时漂移 | 大改动（服装/动作） |
| 纯 prompt t2i | **弱** —— 只能生成"同类角色"，具体设计必丢 | 无参考图的原创/原作角色 |
| 风格 LoRA | **几乎无效**（被 aesthetic-boost 压住，1.5 强度也压不住） | 不推荐 |
| 画师 tag 写进 prompt | **有效，差异明显** | 画风探索（wlop/kantoku/hiten…） |

## 五、环境坑（Windows + 沙箱）

| 现象 | 原因 | 解法 |
|---|---|---|
| ComfyUI 跑几批后**无异常猝死**（日志停在进度条中间） | agent 启动的 GPU 进程被沙箱静默 SIGKILL | **让用户手动启动** ComfyUI 常驻 |
| `httpx.InvalidURL: Invalid port: ':1]'` | harness 注入的 `NO_PROXY` 含 `[::1]`，httpx 解析不了 | 进程内清掉 NO_PROXY（`run_tagger.py`） |
| HF 大文件下载中断（urllib/PowerShell 都卡死） | 原站 CDN 传输不稳 + Schannel 限制 | **走 `hf-mirror.com`**，秒过 |
| danbooru API 403 | 反爬/代理封锁 | 用 **safebooru.donmai.us**（同 tag 体系，SFW） |
| `node run_workflow_args.js` 报 EPERM | 沙箱禁止 spawnSync 管道 | 直接调 `comfyui-skill` 或自己 POST `/prompt` |
| PowerShell 内联 python `-c` 引号地狱 | 转义层级太深 | **一律写成脚本文件** |
