2. **CG（22 张）与 SE（20 个）的触发时机**
   剧本 DSL 目前只有 `@scene / @enter / @exit / narr: / st: / *choice / @flag / @if / @label / goto / @minigame / @save / @ending`，**没有 CG / SE 指令**。请二选一：
   **(a)** 剧情侧新增 `@cg <id>` / `@se <id>` 并写入剧本（我方扩编译器）；
   **(b)** 给一张「章节/场景/关键节点 → 用哪张 CG、哪个 SE」的对照表，我方在编译器里按规则自动挂。

3. **CG 转 WebP 的建议不能采纳**
   **JavaFX 原生不支持 WebP**（只认 PNG / JPEG / GIF / BMP），转 WebP 后会加载失败。CG 是无透明的 RGB，建议改**转 JPEG（质量 85~90）**或 PNG 量化；要压 hires 同理。请确认可否走 JPEG。

4. **体积策略**
   仅「游戏分辨率 + 前两章引用」= 28 MB（已入库）；**全量游戏版 = 325.9 MB**（不含 hires，hires 另 159.2 MB）。公开仓库长期放 300+ MB 偏重。请选：
   **(a)** 全量入库（一次到位）／**(b)** 随章节编译按需入库（推荐）／**(c)** CG 压 JPEG 后再全量入库。

## 六、一条排错经验（建议写进你们的《经验教训》）

素材刚交付时，我这边出现了「素材明明在磁盘上，游戏里却渲染成一个半透明白方块」。

原因不在素材：引擎的图片解析顺序是「**地图目录内 → classpath（`target/classes`）**」，而 `target/classes` 里还是**上一次构建的旧拷贝**（新素材没有随构建复制进去），于是走了占位图。

**建议**：交付素材后提醒程序侧**重跑一次构建**（或验证前先 `mvnw clean`）。这类问题肉眼很像「抠图没做好」，容易误判成素材问题——实际素材实测是干净的（见第一节）。
