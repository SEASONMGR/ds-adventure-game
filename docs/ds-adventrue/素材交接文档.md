## 二、命名与目录约定 ★

引擎（`com.studio`）在剧本节点里用 **`path =`** 引用素材。**立绘的约定是角色文件夹**：

```
assets/sprites/<角色id>/<表情id>.png          ← 立绘（剧本引用的就是这个形式）
assets/sprites/backgrounds/<场景id>.png        ← 背景
assets/cg/<cgid>.png                          ← CG
assets/sprites/ui/…                           ← UI / 横幅 / 标题
assets/sounds/<seid>.wav                       ← 音效
```

> ⚠️ **注意**：`sprites/` 根目录下还残留一批扁平的 `<角色id>_<表情>.png`（81 张）。
> 那是生产过程的中间产物，**不是剧本引用的形式**。程序侧只需认 `<角色id>/<表情>.png`。
> 如需清理，删掉根目录的扁平 png 即可（不影响任何引用）。

### 3.0 两种表情 id 并存（重要）

角色文件夹里的表情 id 有**两套命名**，**剧本两套都在用**，都必须保留：

- **官方表情 id**：来自《人物设定集》§10.2（如 `ds/smile`、`glm/worried`、`reimu/angry`）
  —— 本轮按这份表全量生产。
- **早期语义 id**：生产过程中曾用过的通用语义（`normal / happy / sad / angry / shy / wink /
  surprised / smug / base` 等），例如已编译剧本里就引用了 `ds/happy.png`、`ds/sad.png`、
  `ds/defect_happy.png`、`glm/angry.png`。

> **两者不可互相替换**：同一个角色的 `happy`（语义）与 `smile`（官方）是**两张不同的图**。
> 程序侧只需按剧本 `path =` 指向的文件名加载，不需要做任何映射。
> 后续章节编译后会引用更多 id，**已交付的素材不会因此作废**。

### 3.1 立绘显示建议（画布 1280×720）

- 立绘源图是 2:3 竖构图，**不要拉伸**，按高度等比缩放
- 建议显示高度 **620~700px**（约画布高的 86~97%），底部对齐画面下沿
- 对话时人物一般居左或居右，中间留给对话框
- 节点写法（参考已编译剧本）：

```
{
type = char
id = char_ds
x = 480
y = 150
width = 320
height = 520
path = assets/sprites/ds/normal.png
opacity = 1.0
}
```

> ⚠️ **半透明立绘**：`ds/whale_cute.png`、`ds/whale_cry.png`（残缺鲸形态）
> 自身带 alpha（约 42~49% 半透明像素），**渲染时必须尊重 alpha 通道**，
> 不要做 alpha 预乘或强制不透明处理，否则会丢掉「缺鳞透光」的演出效果。
